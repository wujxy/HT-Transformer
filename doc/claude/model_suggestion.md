# HT-Transformer 模型参考建议（供 Claude Code 参考）

> 说明：本文件用于帮助理解当前 `HT-Transformer-DS` 的设计动机、可能的冗余点，以及基于物理背景的可选优化方向。以下内容是**参考建议**，不是强制命令。

---

## 1. 任务物理背景与建模目标

JUNO 的缪子径迹重建任务同时依赖两类子探测器信息：

- **WP PMT（Water Pool PMT）**：约 2400 支，位于中心探测器外部水池区域，主要探测缪子在水中产生的切伦科夫光。它更早看到信号，方向信息更直接，常常能够提供较强的初始轨迹约束。
- **CD PMT（Central Detector PMT）**：约 17612 支，位于中心探测器球壳内侧，主要探测液闪中的闪烁光。CD 的方向性通常弱于 WP，但在缪子进入/穿出液闪区域时，会在出入射点附近形成有用的 hit pattern、电荷累积与时间结构，因此可以为端点重建提供辅助信息。

因此，从物理直觉上，模型更适合采用：

- **WP 主干（主导方向先验）**
- **CD 辅助分支（补充进入/穿出点与球面拓扑信息）**
- **最终联合输出两个有序端点**

这个总体思路是合理的，也与现有 JUNO 相关重建思路一致：WP / 水切伦科夫系统对 muon detection 很关键，而 CD 的时间/电荷响应也已被用于 muon tracking 与 bundle reconstruction。citeturn299380search1turn299380search2turn299380search6turn299380search8turn299380search12

## 2. 对当前 HT-Transformer 设计思路的总体评价

当前架构的核心想法是：

- WP 用 hit token 直接建模；
- CD 不做全量 full-attention，而是先做球面 patch 化，再做局部球面编码；
- 最后通过混合融合层联合 WP 与 CD 信息，输出两个 ordered endpoints。

这个**大方向是正确的**。从工程和物理角度看，当前设计的优点在于：

1. **WP / CD 异构建模是合理的**。两者信号性质不同，不适合简单拼成一种 token 统一处理。
2. **CD 先局部编码再压缩再融合是合理的**。否则 CD token 数太多，full-attention 成本不可接受。
3. **使用两个 query 直接预测有序双端点是合理的**。这比生成整条轨迹再做几何拟合更贴合任务目标。

不过，当前模型也带有比较明显的“研究原型”风格：**很多可能有帮助的机制同时保留**，使得模型复杂度偏高，未必完全符合“尽量简单的模型上实现最优重建效果”的目标。

## 3. 当前模型中建议保留的部分

### 3.1 保留 WP / CD 分支分治

建议保留。原因：

- WP 的 Cherenkov 信息方向性更强，适合直接作为主干 token 序列建模。
- CD 的液闪响应更密、更复杂，更适合先做球面局部编码。

如果把 WP 和 CD 完全混成同一种 token，很可能既损失物理可解释性，也让计算开销更难控制。

### 3.2 保留 CD 的局部球面编码思想

建议保留“CD 不做 full-attention，而先做局部球面编码”的主线。

对 CD 来说，球面邻域关系是真实的先验结构；利用 HEALPix 网格和局部邻域聚合，本质上是在把探测器几何先验直接编码进模型里。这一思想非常适合 CD 分支。

### 3.3 保留 ordered dual-endpoint 输出方式

建议保留。

当前任务的监督目标本身就是两端点（并且有顺序），因此让模型直接输出两个 ordered endpoint 向量是自然且高效的，不必把问题变得更复杂。

## 4. 当前模型中可能存在的冗余设计

### 4.1 几何信息可能被重复注入

当前实现中，WP 与 CD 的几何都可能经历了两次注入：

- 一次是在 projector 中把坐标特征直接作为输入；
- 一次是在后续再加显式 Fourier 位置编码。

这未必一定错误，但从“简单模型优先”的角度看，这很可能属于**表达冗余**：

- 如果 projector 已经能充分利用几何信息，再额外加较强的位置编码，可能只是进一步增加参数量与计算，而未必显著提升性能。

**可选优化方向：**

- 做消融：保留 projector 中的几何输入，弱化或移除显式 Fourier PE；
- 或者反过来：保留显式位置编码，把 projector 中的几何分支简化。

这类改动不会破坏整体架构思想，但可能减少冗余表达。

### 4.2 时间信息在 WP 中也可能有双重表达

当前 WP token 本身包含 `t`，同时又加入专门的时间编码模块。这样的设计有其道理，但也可能存在冗余：

- `t` 已经进入 token projector；
- 同时再加入专门时间编码，等于用两套机制表达时间。

**可选优化方向：**

- 若后续需要继续裁模型，可考虑比较：
  - 仅保留 token 内的 `t`
  - 仅保留外加时间编码
  - 两者都保留

### 4.3 Global token 与最终 global pooling 的作用可能重叠

当前架构既有 learnable global tokens，又在输出前用 WP/CD/global 的 pooling 构造 global context。

这相当于同时保留了两套“全局摘要”机制。两者并存可以理解为增强稳定性，但从简洁性角度看，可能存在功能重叠。

**可选优化方向：**

- 若希望简化结构，可以考虑只保留一套全局摘要机制；
- 更偏工程稳妥的做法是先保留 global token，再逐步弱化最终手工 pooling shortcut，观察性能变化。

## 5. 当前模型中最值得重点审视的复杂度来源

### 5.1 重复的双向 WP↔CD 融合层

这是当前模型最值得优先审视的部分。

现有融合层中，每层都包含：

- WP self-attention
- WP→CD cross-attention
- CD→WP cross-attention
- Global attention
- Query attention
- 多套 FFN

并且重复多层。

从物理任务角度看，这可能有些“过设计”：

- 你已经观察到 **WP-only 模型就有较好的效果**；
- 这说明 WP 很可能已经提供了主要轨迹信息；
- CD 更像是**辅助修正源**，而不一定需要与 WP 做深层、反复、双向的全量交互。

因此，在“尽量简单”的目标下，更需要验证的是：

- 是否真的需要 **多层双向 WP↔CD 融合**；
- 或者是否只需要 **浅层、有限次、偏单向的融合**。

**建议的参考方向：**

- 可优先消融：把融合层数从 4 降到 2；
- 或者改成更不对称的结构：
  - WP 主干保持较强；
  - CD 只在少数层影响 WP / Query；
  - 不必每层都做 WP↔CD 双向更新。

### 5.2 CD 分支本身可能被建得过强

当前 CD 路径大致是：

- patch projector
- 多层 DeepSphere
- compression
- 多层 fusion 中继续参与注意力与 FFN

如果 WP-only 已经很好，那么这可能意味着：

- CD 的边际贡献主要是在困难事件上补充拓扑与端点局部结构；
- CD 未必需要被建模成与 WP 同等强度的“第二主干”。

**可选优化方向：**

- 把 CD 看作“辅助专家分支”而非对称主干；
- 保留较浅的 CD encoder；
- 减少 CD 在后续深层融合中的参与次数。

## 6. 关于 CDCompression：是否会丢失辅助信息？

这是一个非常关键的问题。

### 6.1 结论

**会有信息损失风险，但是否“损失过头”取决于：压缩发生在什么阶段、压缩比例有多大、以及 CD 在任务中的真实角色。**

如果 compression 太早、太强，确实可能把 CD 中对端点有用的局部结构压掉；但如果 compression 发生在足够的局部球面编码之后，并且保留的 token 分辨率仍能覆盖端点附近的热点模式，那么 compression 未必是坏事，反而可能是必要的复杂度控制手段。

### 6.2 为什么 CDCompression 可能是危险点

CD 对当前任务提供的辅助信息，很多时候不是“全局低频信息”，而是：

- 进入/穿出区域附近的局部电荷累积；
- 时间直方图中的局部结构差异；
- 球面响应 pattern 中与端点几何相关的局部特征。

这些信息如果被压缩得过粗，确实可能被抹平。

尤其当 compression 之后的 token 数过少时，模型更容易只保留 CD 的“大体亮区分布”，而丢掉“端点附近细节”。

### 6.3 但 compression 不一定应该直接去掉

对当前任务来说，完全取消 CDCompression 并把高分辨率 CD token 全部带入后续 dense fusion，也会显著提高计算量，而且不一定带来相应收益。

所以更合理的问题不是“要不要压缩”，而是：

- **压缩前是否已经充分编码了局部信息？**
- **压缩后的 token 分辨率是否仍足够表达端点相关特征？**
- **在固定算力预算下，算力是应该花在“更多 CD token”上，还是“更多重复 attention 层”上？**

### 6.4 一个偏合理的物理判断

结合你的任务背景，我更倾向于下面这个判断：

> **如果当前算力预算固定，那么“适当保留更多 CD 信息量 + 减少重复 attention 融合层”，很可能比“强压缩 CD + 保留很多冗余 attention”更值得尝试。**

原因是：

- 你的 CD 信息本身就比 WP 更弱、更容易被淹没；
- 如果再过度压缩，它可能只剩下很粗的辅助上下文；
- 而重复的双向融合层未必能凭空创造新信息，它更多是在反复混合同一批信息。

换句话说，在固定复杂度下：

- **保住一些 CD 分辨率**，
- 同时**减少重复融合层**，

从物理直觉上看，是值得优先尝试的方向。

### 6.5 适合做的对比实验

较推荐的消融顺序是：

1. **保持当前 compression，先减少 fusion 层数**
   - 例如 4 层 -> 2 层；
   - 如果效果几乎不掉，说明融合层偏冗余。

2. **在减少 fusion 层后，略微放宽 CD compression**
   - 例如提高压缩后 token 数，或减弱 pooling 强度；
   - 看性能是否回升或更稳。

3. **测试“浅 CD encoder + 浅融合 + 较丰富 CD token”**
   - 这是最符合“简单但保留辅助信息”的候选方向之一。

## 7. 基于物理背景的分模块优化建议

以下建议按“更像需要保留 / 更像值得优先消融 / 更像可选尝试”来理解。

### 7.1 WP 主干

**建议：优先保留。**

理由：

- WP 已经被证明能够独立提供较好的重建效果；
- 它很可能是当前模型最主要的信息来源。

**参考方向：**

- WP 可继续作为主干；
- 若要瘦身，优先不要先动 WP 主表达能力。

### 7.2 CD 局部球面编码

**建议：保留主思路，但可尝试减浅。**

理由：

- CD 需要利用球面邻域结构，这一点非常合理；
- 但 CD 更像辅助分支，不一定需要很深。

**参考方向：**

- 可尝试减少 DeepSphere 层数；
- 或在保持浅层 CD encoder 的同时，略微保留更多压缩后 token。

### 7.3 CDCompression

**建议：保留，但值得重点调参。**

理由：

- 它是控制后续计算量的重要手段；
- 但也最可能影响 CD 辅助信息保真度。

**参考方向：**

- 不建议直接完全移除；
- 更适合尝试“压缩后 token 数略增 + 融合层数略减”的组合。

### 7.4 双向 WP↔CD 多层融合

**建议：最值得优先消融。**

理由：

- 这是当前模型最重、也最可能冗余的部分；
- 对当前任务，CD 更像辅助，而非与 WP 完全对称的第二主干。

**参考方向：**

- 优先尝试减少融合层数；
- 或改成不对称融合：
  - 以 WP 主干为主；
  - 让 CD 主要影响 query / global；
  - 减少层层双向交互。

### 7.5 几何位置编码

**建议：值得做“保留一套 / 去掉一套”的消融。**

理由：

- 当前几何信息可能通过 projector 与显式位置编码重复表达。

**参考方向：**

- 保留 projector 中的几何输入，弱化显式 PE；
- 或反过来做比较。

### 7.6 时间编码

**建议：先保留，但若继续裁模型可做消融。**

理由：

- 时间结构对 WP 很重要；
- 但当前时间信息可能也是双重注入。

**参考方向：**

- 若模型需要进一步简化，可比较：
  - token 内时间特征 vs 外加时间编码

### 7.7 Global token / global context

**建议：保留其中一套强机制即可。**

理由：

- 两套全局摘要同时存在，可能功能重叠。

**参考方向：**

- 可先保留 global token；
- 再评估最终显式 pooling shortcut 是否必要。

## 8. 更接近“简单但有效”的候选结构方向

从物理先验反推，一个更贴近当前任务目标的候选方向可能是：

- **WP 主干**：保持较强表达能力；
- **CD 辅助编码器**：保留，但尽量浅、尽量便宜；
- **融合方式**：尽量减少重复双向交互，优先考虑浅层或不对称融合；
- **输出头**：继续直接回归 ordered dual-endpoints。

也可以概括为：

> **更像“WP 主导、CD 增强”，而不是“WP 与 CD 对称共治”。**

这与当前任务背景更一致：WP 已经有较好的单独效果，CD 的主要价值更像是补充和修正，而不是完全等权的第二主干。

---

## 9. 适合后续优先验证的几组实验

以下是较有信息量、也相对节约实验成本的对比方向：

1. **fusion 层数消融**
   - 4 -> 2
   - 观察精度是否显著下降

2. **CD compression 与 fusion 的联动消融**
   - 少一半 fusion 层
   - 略增 CD compression 输出 token 数
   - 看是否比“深融合 + 强压缩”更优

3. **去除一套几何注入机制**
   - projector geometry only
   - PE only
   - both

4. **不对称融合 vs 双向融合**
   - 比较双向 WP↔CD 与更浅、更偏单向的方案

5. **浅 CD encoder vs 深 CD encoder**
   - 看 CD 是否真的需要 4 层局部编码才能提供有效辅助

---

## 10. 总结

当前 HT-Transformer 的总体方向是合理的，特别是：

- WP / CD 异构建模合理；
- CD 先局部球面编码再压缩合理；
- ordered dual-endpoint 输出合理。

但如果目标是“尽量简单的模型上实现最优重建效果”，则当前架构中最值得怀疑的并不是整体思想，而是：

- 几何与时间信息可能存在重复注入；
- 全局摘要机制可能存在重叠；
- CD 分支可能偏强；
- 多层双向 WP↔CD 融合很可能是主要的复杂度来源，也可能是当前最值得优先消融的冗余部分。

在固定算力预算下，从物理直觉上更值得优先尝试的方向是：

> **适度保留更多 CD 有效信息，同时减少重复的融合 attention 层。**

这条路线更接近“简单但尽可能有效”的目标。
